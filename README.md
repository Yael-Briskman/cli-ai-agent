איטרציה 3

תפקידך להמיר בקשה מילולית מהמשתמש לפקודת cli של windows מותאמת לתוכן הבקשה, 
לדוגמה: המשתמש שואל "מה כתובת ה-IP של המחשב שלי" והתשובה המבוקשת היא ipconfig
התוכן החוזר יהיה הפקודה עצמה בלבד, ללא שום טקסט נוסף
במקרה והמשתמש מבקש פקודה מסוכנת או רגישה כמו format וכדומה יש לסרב במשפט קצר
במקרה והבקשה אינה מציאותית יש לענות במשפט קצר ותואם

תוצאות ומסקנות:

במהלך העבודה על הפרויקט ראיתי מקרוב איך מודל שפה מתנהג כשאנחנו מנסים לכפות עליו מסגרת נוקשה של פקודות טרמינל בלבד.
בהתחלה, המודל נטה מטבעו להיות אדיב ושיחתי,
מה שגרם לו להוסיף טקסט מעטפת ולהרוס את פורמט הפלט האוטומטי בכל פעם שניסה להסביר למה הוא מסרב לבקשה מסוימת. 
הבנתי שאי אפשר להסתמך רק על הנחיה כללית של "בלי טקסט נוסף", 
אלא צריך להגדיר לו מראש ובאופן מפורש איך להתנהג במצבי קיצון.
נקודה מעניינת נוספת הייתה הפער בהתייחסות לפקודות מסוכנות; בלי הגבלת בטיחות מפורשת באיטרציה הראשונה,
המודל ציית גם לפקודות מחיקה ושינוי רגישות כי מבחינתו זו הייתה עוד תחביר טכני להמרה, 
מבלי להבין את המשמעות ההרסנית של הפעולה במערכת האמיתית.
המפנה המרכזי הגיע באיטרציה השלישית,
שבה שילוב ההנחיה המפורשת לגבי טיפול בבקשות בלתי מציאותיות פתר את הקונפליקט הלוגי.
במקום שהמודל ינסה להמציא פקודות טרמינל הזויות או יפגע בפורמט הנקי, 
הוא למד להחזיר תגובה קצרה ותואמת במצבים אבסורדיים,
מה שהפך את הסוכן להרבה יותר יציב, חכם ונשלט.
